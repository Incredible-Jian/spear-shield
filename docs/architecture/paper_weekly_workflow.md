# 模拟账户与每周研究闭环

适用：2026-11-09 实用化第三轮。冻结策略版本仍为 `delegated-2026-11-03-v1`。研究裁决不自动下单；所有本轮成交均为模拟。

## 日常使用

1. 打开现有桌面软件，更新 Dashboard 的六标的研究行情。模拟交易另需在账户页更新所选ETF的**原始行情**；不能用前复权价代替。
2. 模拟账户页初始化资金，默认100000元，已有账户不允许覆盖。旧版本账户须点击“确认旧账户当前状态”，仅建立当前可知起点，不回填过去。
3. 选择ETF、份额，使用“原始缓存参考价模拟买入/卖出”。未收盘或最近更新失败时，默认阻止；只有用户明确勾选对应许可才可使用有日期/来源标签的参考价。超过4个自然日的缓存仍阻止，节假日也保守暂停，不暗中放宽。
4. 本次份额上限0表示全部，正数表示人为设定的部分成交上限，不是盘口推算。选中未完成订单可重试或取消余量；不会回滚已经发生的模拟成交。
5. 策略信号页“生成本周策略裁决”，审阅条件、UNKNOWN、完整性、来源与建议状态；再点击“确认保存快照”。确认只保存研究记录。
6. 周报页点击“基于最近确认裁决生成周报”，从下拉框查看历史，导出Markdown、CSV数据包或Excel；沿用原PDF入口。不选择历史时的缓存观察报告与已确认周报明确区分。

## 复用和数据模型

沿用 `paper_account` 的账户、持仓和逐笔账本，金额以万分之一元整数保存。没有把回测账户对象、ATR执行日志或策略目标搬入纸面账户。

| 职责 | 模型/表 | 语义 |
|---|---|---|
| Account | PaperAccount / paper_account | 初始资金与现金，原有表 |
| Position | PaperHolding / paper_holding | 份额和累计成本，原有表 |
| 已有财务账本 | PaperTrade / paper_trade | 实际发生的模拟记账，保留旧记录 |
| Account起点 | PaperAccountOrigin / paper_account_origin | 可知时间和新建/旧账户明确确认方式 |
| Order | PaperOrder / paper_order | 独立订单ID、不可复用改变的意图、当前状态及原因 |
| Fill | PaperReceipt / paper_receipt | 独立回执ID，关联order_id/trade_id，参考价与模型价、日期、来源、费用和模型时间 |
| 订单状态审计 | PaperOrderEvent / paper_order_event | 追加状态变化，含累计成交量；重复状态不重复追加 |
| AccountSnapshot | PaperEquityMark / paper_equity_mark | 带时点和行情明细的资产记录；缺价返回UNKNOWN而非零 |
| RiskEvent | PaperRiskEvent / paper_risk_event | 裁决中的ATR风险**观测**，明确NOT_EXECUTED，不冒充止损成交 |
| 周裁决 | WeeklyDecision / weekly_decision | 用户确认后的完整JSON、截止时点、SHA256、策略版本 |
| 周报 | WeeklyReportRecord / weekly_report_record | 绑定已确认快照，不重新读取后来的行情 |

新增8张表；旧3张账户表及行情表不改列、不重置。`SchemaVersion`沿用现有0.1.0引导记录，不把表存在误称为新策略版本。

## 增量数据库方案

发布前先使用已有数据管理备份功能或SQLite backup API保存原库副本；不要在程序运行中直接拷贝一个可能正在写入的数据库。本轮实际用SQLite backup从上一轮真实缓存复制到隔离目录，未改正式用户库。

`Database.init()`注册新模型并执行 `create_all`，只创建不存在的表，可重复执行。旧账户起点不凭空推断，需要用户确认，历史成交不伪造新的来源。测试覆盖旧库状态、重复初始化、余额不被重置以及关闭重开。

本轮无删除/改列迁移，无数据回填，无Git历史处理。若回退应用版本，先保留完整备份；旧版无法展示新表，不能把此情况说成数据丢失或自动删表。当前没有引入大型迁移框架。

## 执行状态与事务

`AccountPage → execute_reference_order → 原始价时点/质量门控 → paper_account.trade → PaperReceipt → mark_equity → finish_order → commit`。

订单为 `PENDING → PARTIAL → FILLED`；PENDING/PARTIAL可以CANCELLED，明确非法交易可REJECTED。没有回执就没有成交。重试必须保持同一订单意图；同一order_id+attempt_id只记账一次。用户要求新的部分成交时创建新的attempt_id。撤单幂等，保留已成交量、成本与现金。

SQLite写入在读余额前获取 `BEGIN IMMEDIATE` 写锁；财务账本、回执、状态与资产快照同一事务。写入失败调用者回滚，不留下“现金已扣、成交不存在”的半状态。UI异常返回明确提示，不自动重复成交。更新失败不自动转用手工价。

买入增加含买入费用的成本，卖出按现有整数比例分摊成本，清仓分摊全部剩余成本，费用立即计入现金；收益与账本复核。费率0.0003、滑点0.0005沿用现有 `backtest/models.py` 研究参数，本轮未更改冻结规则。159915/563020施加模型T+1约束，部分成交限制为用户情景假设。

## 时点、UNKNOWN与不可变记录

研究数据只取截止时点前已经写入的缓存；宏观缓存的获取时间作为更保守的可知时间下限，不把研究假设的发布时间冒充真实历史发布版本。历史自定义时点不能回填当前账户；账户状态或生命周期缺失保持UNKNOWN。

本周/月完成性依赖独立交易日历、对应交易日样本、校验及15:30后的缓存写入。上一个完整周/月可作观察，但不能冒充当前周期已完成。账户净值缺失、过期或更新失败时，账户相关正式裁决关闭。

条件保留True/False/None，并在导出显示TRUE/FALSE/UNKNOWN。规则有已知否决条件时可不触发，但其余UNKNOWN仍逐项列出，不改写成False。档位、峰值和补回等策略生命周期不从手工持仓猜测。

`prepare_weekly → 审阅草稿 → confirm_weekly → WeeklyDecision → make_weekly_document → WeeklyReportRecord → export_document`。

确认前不写历史裁决，确认时检查内容哈希。同ID同内容重复确认幂等，同ID不同内容拒绝。报告只读对应已确认快照；后续更新不改变历史。不可变约束在应用服务层实现，不是防止用户直接改写SQLite的安全边界。

## ATR边界与当前限制

本轮未改ATR触发、旧目标取消、执行回执或冻结参数。周度ATR记录是观察，不自动生成止损订单。账户页手动提交的模拟订单代表新用户意图，不读取或恢复旧策略目标。新研究裁决有独立UUID；正式策略目标的撤销/新建语义仍由既有执行层负责，旧复现和新目标ID测试保留。

这是缓存参考价情景模拟，不是交易所撮合：不承诺当时可执行价格、真实成交、完整申报单位、市场流动性、完整公司行动/分红或税费。价格超过4自然日的限制属于模拟数据新鲜度门控，不属于冻结交易策略，长假可能暂停新操作。

旧版手工价格功能为兼容保留，按钮明确标记“价格未核验”，回执来源USER_INPUT_UNVERIFIED，滑点UNKNOWN，不作为真实缓存缺价降级路径。升级前的旧账本保留原貌，不能补造历史回执与来源。

QVIX、股债定义/尺度、部分基本面历史发布版本仍有缺口；报告可保存部分结论，不宣称完整策略通过验收。Windows安装包和自动策略执行不在本轮交付范围。
